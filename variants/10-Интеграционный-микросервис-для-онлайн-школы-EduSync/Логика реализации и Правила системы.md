### 1. Матрица коммуникаций во Внутреннем сервисе

Микросервис, создавая пользователей и чаты во Внутренней системе, должен опираться на следующие доступы:

| Роль инициатора   | Может писать Ученику |    Может писать Преподавателю    | Может писать Администрации (ОРК) | Может писать Отделу Продаж |
| :---------------- | :------------------: | :------------------------------: | :------------------------------: | :------------------------: |
| **Ученик**        |         Нет          | Да (своему)<br>(если баланс > 0) |                Да                |            Нет             |
| **Преподаватель** | Да (своим ученикам)  |               Нет                |                Да                |            Нет             |
| **Администрация** |          Да          |                Да                |                Да                |             Да             |
| **Отдел продаж**  |          Да          |               Нет                |                Да                |             Да             |

### 2. Ключевые пользовательские сценарии (Use Cases) для Микросервиса

*   **UC-1: Регистрация нового ученика.** Триггер: Webhook от AmoCRM (смена статуса на "Оплачено"). Действие: Запрос в API AlfaCRM (создание карточки), генерация пароля, запрос в API Внутренней системы (создание юзера), отправка данных в AmoCRM (комментарием).
*  **UC-2: Ежедневная проверка баланса.** Триггер: CRON. Действие: Запрос учеников из AlfaCRM, фильтрация тех, у кого баланс ≤ 1 урок. Отправка POST-запроса во Внутреннюю систему для генерации уведомления и системного сообщения в чат "Ученик-ОРК".
*  **UC-3: Блокировка/Разблокировка доступов.** Триггер: Webhook от AlfaCRM (изменение баланса). Действие: Запрос во Внутреннюю систему на блокировку/разблокировку конкретного чата (Ученик-Преподаватель) через смену статуса чата, отправка уведомления Администрации.
