# Белый список и ограничения доступа в городах выезда

**Кому:** аналитикам по контуру «выездная заявка → чат → CRM»  
**От кого:** ИТ и информационная безопасность ООО «РИАТПО-Сервис»  
**Дата:** 11.09.2026  
**Статус:** как есть, не проект решения

В городах Зареченск, Октябрьский и Северная промзона Приволжска с весны 2026 действует фильтрация исходящего трафика на уровне городских операторов. С SIM корпоративных телефонов, с гостевого Wi-Fi клиентов и с большинства «домашних» каналов инженера открываются только узлы из регионального белого списка. Список нам **не согласовывают** и **не расширяют** под коммерческий портал.

Офис в Приволжске (площадка бесконтактной линии) работает через собственный канал: Bitrix24 оттуда доступен. Полевой контур — нет.

## Что открывается у выездного специалиста «в городе»

| Сервис | Доступ из полевой сети | Комментарий |
|--------|------------------------|-------------|
| Мессенджер Яндекс 360 (приложение и web) | да | основной живой канал; организация `riatpo-service.ru` |
| Почта и Диск Яндекс 360 | да | почтой заявки не ведём — нет дисциплины и поиска |
| Телемост Яндекс 360 | да | для созвонов, не для учёта заявок |
| Госуслуги / ЕПГУ | да | к контуру выезда не относится |
| Корпоративная почта на домене (через 360) | да | |
| Портал Bitrix24 `riatpo-service.bitrix24.ru` | **нет** | DNS/HTTPS режутся; мобильное приложение не логинится |
| Входящий вебхук и REST Bitrix24 | **нет с телефона инженера** | до портала достучится только хост вне фильтра (офис, наш сервер) |
| Корпоративный VPN | нет в указанных городах | шлюз не в белом списке; ИБ запретила «любой личный VPN» приказом 14/ИБ от 12.04.2026 |
| Telegram, WhatsApp, MAX (как рабочий контур) | нет / не используем | в белом списке их нет либо нет корпоративных аккаунтов |

Точный перечень IP и SNI ИБ в эту папку не кладёт. Для постановки задачи достаточно правила: **поле видит Яндекс 360 и не видит Bitrix24. Офис и сервер интеграций видят оба.**

## Технические следствия, которые уже проверили

1. Пуш и почта из Bitrix24 «задача назначена» до телефона в Зареченске не доходят: хост портала недоступен, клиент Bitrix не удерживает сессию.
2. Короткая ссылка на карточку сделки из чата **не помогает**: по нажатию открывается тот же заблокированный портал.
3. Приложение Мессенджера Яндекс 360 у всех штатных инженеров установлено, логины заведены в организации 360. Боты организации могут писать сотрудникам и принимать ответы (см. файл по Bot API).
4. Сервер в офисном контуре (или облако, которое резолвит и `bitrix24.ru`, и `botapi.messenger.yandex.net`) — единственное место, откуда можно одновременно дергать REST Bitrix24 и Bot API. С телефона инженера такой «мост» собрать нельзя.
5. Выкладывать карточку клиента целиком в групповой чат ИБ не согласует: адреса объектов и коды доступа — персональные и коммерческие сведения. Канал до специалиста должен быть **персональным**, не «общим котлом».

## Чего ИТ просит не предлагать

- Внести `*.bitrix24.ru` в региональный белый список — вне нашей компетенции, заявки в администрацию уже отклоняли.
- Раздать полевым личный VPN / «серые» обходы — прямо запрещено приказом 14/ИБ.
- Перенести учёт заявок в Диск, таблицу или сам чат как в новую систему записи.
- Открыть Bitrix24 наружу через наш собственный реверс-прокси «чтобы приложение открылось» — это обход фильтра и отдельный контур безопасности, в рамки этой работы не входит.

Если для концепции нужен стенд: офисный хост с исходящим доступом к обоим API у нас есть, токены выдадим по запросу на установочной, в файлы репозитория секреты не класть.
