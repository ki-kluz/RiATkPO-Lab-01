## БЛОК 2. Описание существующей внутренней системы компании (Legacy ERP «СтройБаза-4.2»)

ERP управляет заказами, но не имеет встроенных логистических интеграций. Все действия ранее выполнялись кнопками оператора вручную.

### Жизненный цикл заказа в ERP (Текущие статусы)

1. `NEW` (Новый) — заказ создан клиентом на сайте, ожидает оплаты или подтверждения.
2. `CONFIRMED` (Подтвержден) — резервы на складе списаны, оплата получена.
3. `ASSEMBLING` (На комплектации) — передан на терминал сбора данных (ТСД) кладовщика.
4. `ASSEMBLED` (Скомплектован) — сборка физически завершена, заказ лежит в зоне отгрузки.
5. `SHIPPED` (Отгружен) — загружен в автомобиль (на данный момент ставится вручную оператором по бумажному реестру).
6. `DELIVERED` (Доставлен) — закрывающий статус (ставится вручную через 1–3 дня после отгрузки).
7. `CANCELLED` (Отменен) — заказ аннулирован.

### Технические ограничения ERP

- База данных: PostgreSQL 11. Прямой доступ к БД извне закрыт (Security Policy). Взаимодействие только через внутренний REST API шлюз.
- **Cron-задачи:** Фоновые процессы синхронизации статусов не должны запускаться чаще, чем раз в 5 минут, во избежание дедлоков в таблице orders.
- **Весогабаритные характеристики (ВГХ):** Хранятся в таблице nomenclature_dim:
    - weight_netto (граммы, integer)
    - length_mm, width_mm, height_mm (миллиметры, integer, могут быть NULL для архивных позиций).
- В таблице orders на данный момент **нет полей** для хранения внешнего идентификатора отправления, ссылки на PDF-этикетку и трек-номера ТК.

## БЛОК 3. Выдержка из документации внешнего сервиса (API ТК «ГрузВектор v2»)

Интеграция осуществляется по протоколу HTTPS. Формат данных: JSON. Аутентификация: Bearer Token в заголовке Authorization.

### 3.1. Метод: Предварительный расчет тарифа доставки

- **URL:** POST /api/v2/calculator/tariff
- **Ограничение (Rate Limit):** Не более 5 запросов в секунду от одного аккаунта.
- **Входные параметры:**
    - sender_city_fias (string, UUID, обязательное) — ФИАС склада отправления.
    - receiver_address (string, обязательное) — строковый адрес доставки для геокодинга.
    - cargo_places (array of objects, обязательное) — список грузовых мест:
        - weight (number, кг, обязательно)
        - length, width, height (number, метры, обязательно)
            
- **Бизнес-правило ТК:**
> [!NOTE]
> Расчётная стоимость определяется по формуле:
> $$\text{Cost} = \max(M_{\text{real}}, M_{\text{vol}}) \times \text{Tariff\_Rate},$$
> где объёмный вес рассчитывается как: 
> $$M_{\text{vol}} = \frac{\text{Длина (см)} \times \text{Ширина (см)} \times \text{Высота (см)}}{500}$$
> Если хотя бы одно измерение упаковки превышает 2,2 метра, применяется наценка «Негабарит» (+40% к тарифу). Максимальный вес одного места — 1500 кг.

### 3.2. Метод: Регистрация заказа на доставку

- **URL:** `POST /api/v2/orders/create`
- **Входные параметры:**
    - `client_order_id` (string, обязательное, max 32 chars) — внутренний номер заказа в системе ритейлера. Должен быть уникальным.
    - `recipient` (object, обязательно):
        - `name` (string), phone (string, строго в формате E.164: +7XXXXXXXXXX).
    - `delivery_point` (object): координаты или структурированный адрес (город, улица, дом, корпус/строение, квартира/офис).
    - `pickup_date` (string, date: YYYY-MM-DD). Заказы на текущий день принимаются только до 13:00.
    - `places_count` (integer, количество грузовых мест).
    - `items` (array) — товарная номенклатура для формирования сопроводительных документов.
- **Ответ (Success 201):**
    - `gv_tracking_number` (string, трек-код вида GV-992-XXXXX).
    - `order_status` (string, принимает значение REGISTERED).
    - `label_url` (string, прямая ссылка на формирование стикера в формате PDF/ZPL).

### 3.3. Метод: Получение этикетки грузового места

- **URL:** `GET /api/v2/orders/{gv_tracking_number}/label?format={pdf|zpl}`
- Возвращает бинарный файл этикетки 100×150 мм для термопринтера.

### 3.4. Уведомления об изменении статусов (Webhooks)

Сервис ТК умеет отправлять POST-запрос на endpoint Партнера при смене статуса доставки.

- **Формат Payload:**

```json
{
  "event": "STATUS_CHANGED",
  "client_order_id": "ORD-2026-9811",
  "gv_tracking_number": "GV-992-00123",
  "new_status": "COURIER_ASSIGNED",
  "timestamp": "2026-10-25T14:32:10Z",
  "comment": "Водитель Иванов А. назначил выезд с 15:00 до 18:00"
}
```

- **Справочник статусов ТК «ГрузВектор»:**
    - `REGISTERED` — Заказ зарегистрирован в системе ТК.
    - `ACCEPTED_AT_WAREHOUSE` — Груз принят на терминале ТК / принят курьером у продавца.
    - `IN_TRANSIT` — Заказ перемещается между хабами.
    - `COURIER_ASSIGNED` — Передан курьеру «последней мили».
    - `DELIVERED` — Успешно вручен покупателю.
    - `DELIVERY_FAILED` — Попытка вручения неудачна (клиент недоступен / отказ).
    - `CANCELED` — Доставка отменена.
        
- **Важное условие безопасности ТК:** Партнер обязан отвечать HTTP-кодом 200 OK в течение 3000 мс, иначе ТК повторяет отправку хука с экспоненциальной задержкой до 5 раз, после чего отключает webhook-нотификации для магазина до ручного сброса через поддержку.
